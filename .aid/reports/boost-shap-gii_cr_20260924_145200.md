      <location file="boost-shap-gii_brainstorm_20260924_140000.md" lines="T2" />
      <description>The brainstorm does not specify whether the config hash is computed from the raw config (from load_config/yaml.safe_load) or the resolved config (after fill_config_defaults fills data-driven defaults). train.py calls fill_config_defaults (modifying the config in-place); predict.py and infer.py do not.       <evidence>train.py calls fill_config_defaults(config, n_rows, n_features). predict.py calls load_config(args.config) without filling defaults. The hash method "json.dumps(filtered_config, sort_keys=True, default=str)" does not specify which config state is hashed.</evidence>
      <literature>N/A (codebase verification)</literature>
      <impact>Cross-stage asymmetry: predict cannot recompute train's hash if train hashed the resolved config. Data-change false negative: same config path with different data content produces identical raw-config hashes despite different effective configs.</impact>
      <recommendation>Hash the raw config (pre-defaults) at all stages to ensure cross-stage consistency. Simplify predecessor validation to existence + status check (no hash recomputation), since the superset cascading property already handles config-change propagation. Document explicitly that the hash guards against config-file changes, not data-content changes.</recommendation>

      <location file="boost-shap-gii_brainstorm_20260924_140000.md" lines="T8" />
      <description>T8 specifies "No cascade delete: --force-restart on predict does not delete train's checkpoint." The converse is also true: --force-restart on predict does not invalidate infer's checkpoint. If predict re-runs due to a code-version change and the user does not also force-restart infer, infer would resume from a checkpoint built against predict's old artifacts, producing silently inconsistent results.</description>
      <evidence>The brainstorm's pipeline_version field is informational only, not a guard. The config hash cannot detect upstream artifact changes that occur without a config change.</evidence>
      <literature>N/A (codebase verification)</literature>
      <impact>Silently inconsistent results when a code-version change triggers a selective force-restart without cascading to downstream stages.</impact>
      <recommendation>Add a predecessor_checkpoint_mtime field to predict's and infer's checkpoint schemas. On resume, compare the stored mtime to the current os.path.getmtime() of the predecessor's checkpoint file. If the predecessor's checkpoint is newer (meaning it re-ran after the current stage completed), invalidate the current stage's checkpoint and restart automatically. This subsumes the pipeline_version guard: any predecessor re-run, for any reason, is detected. The cost is one os.path.getmtime() call per resume, and the direction of error is safe (unnecessary re-run, never stale resume).</recommendation>
