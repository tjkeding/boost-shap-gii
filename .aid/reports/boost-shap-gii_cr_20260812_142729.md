    <finding id="F1" severity="minor" category="validity">
      <location file="src/boost_shap_gii/shap_utils.py" lines="1168-1196" />
      <description>
        The _nan_safe_fdr docstring (line 1172) states: "NaN p-values (from failed calculations) are
        excluded from the BH denominator and restored as NaN q-values after correction." The code
        (line 1192) replaces NaN p-values with 1.0 placeholders before passing the full vector to
        multipletests(method='fdr_bh'). The 1.0 placeholders ARE included in the BH denominator m,
        meaning NaN effects inflate the denominator rather than being excluded from it. The NaN
        restoration (line 1194, q_vals[nan_mask_p] = np.nan) is correct.

        The statistical consequence is that surviving (non-NaN) q-values are slightly MORE conservative
        than they would be if failed effects were truly excluded, because m is larger than the number of
        testable effects. This is the safe (conservative) direction, so the test's Type I error control
        is not compromised. However, the docstring's claim of denominator exclusion is factually incorrect
        and could mislead a reviewer or downstream user interpreting the correction's behavior.
      </description>
      <evidence>
        Line 1172: "excluded from the BH denominator"
        Line 1192: p_clean[nan_mask_p] = 1.0
        Line 1193: q_vals = multipletests(p_clean, alpha=alpha_val, method='fdr_bh')[1]

        The BH procedure computes q_i = p_(i) * m / i, where m = len(p_clean), which includes
        the 1.0 placeholders. True exclusion would require passing only p_clean[~nan_mask_p] to
        multipletests and then re-indexing the results.
      </evidence>
      <literature>
        Benjamini and Hochberg (1995): the BH procedure's q-value computation uses m (total number
        of tests) as the denominator. Using a larger m (by including untestable effects as 1.0
        placeholders) increases all q-values, which is equivalent to applying BH with a more
        conservative effective alpha. This is analogous to not pruning the family size when some
        hypotheses are a priori known to be non-rejectable.
      </literature>
      <impact>
        No impact on statistical validity (conservative direction). Risk of reviewer confusion if
        the docstring is cited in a methods section or supplementary material to describe the
        FDR correction procedure.
      </impact>
      <recommendation>
        Correct the docstring to accurately describe the behavior: NaN p-values are replaced with
        1.0 conservative placeholders that remain in the BH denominator (inflating m), and are
        then restored as NaN q-values after correction. Alternatively, implement true denominator
        exclusion by passing only non-NaN p-values to multipletests and re-indexing. The current
        behavior is defensible (conservative), so this is a documentation-accuracy issue, not a
        statistical-correctness issue.
      </recommendation>
    </finding>

    <finding id="F3" severity="minor" category="validity">
      <location file="src/boost_shap_gii/shap_utils.py" lines="1402-1404" />
      <description>
        In inference mode, X_stacked is constructed by tiling fold 0's X_full data K times
        (line 1404: X_stacked = pd.concat([chunks_X[0]] * n_folds, ignore_index=True)). Real
        feature columns are identical across all folds in inference mode (val_idx = all observations),
        so the tiling is correct for real features. However, shadow feature columns differ across
        folds because each fold generates an independent shadow permutation (shap_utils.py line 1339:
        rng = np.random.default_rng(config["execution"]["random_seed"] + fold_idx + 1000)).

        The resulting X_stacked contains fold 0's shadow feature values for ALL K*N rows, while
        the SHAP value matrices (df_shap_shadow_full) contain each fold's shadow SHAP values.
        For folds 1..K-1, the shadow SHAP values are paired with the wrong shadow feature values
        in the V computation. This affects only the shadow V estimates used to build the stratified
        noise distribution for the exceedance test.

        For real effects, the V computation is unaffected (real feature values are identical across
        folds). In OOF mode (non-inference), X_stacked is constructed correctly from all K folds'
        individual data (line 1418: pd.concat(chunks_X).sort_index()), so this issue is specific
        to inference mode.
      </description>
      <evidence>
        Line 1404: X_stacked = pd.concat([chunks_X[0]] * n_folds, ignore_index=True)
        Line 1339: rng = np.random.default_rng(config["execution"]["random_seed"] + fold_idx + 1000)

        In _process_boruta_fold (lines 1334-1363), each fold generates its own shadow permutation
        using a fold-specific RNG seed. The returned X_full includes these fold-specific shadow
        columns. But X_stacked tiles only chunks_X[0], discarding folds 1..K-1's shadow features.

        Contrast with OOF mode (line 1418): X_stacked = pd.concat(chunks_X).sort_index(), which
        correctly preserves each fold's individual data including fold-specific shadow features.
      </evidence>
      <literature>
        The exceedance test compares real effect statistics against the distribution of max-shadow
        statistics. The shadow V component measures the functional variability of shadow SHAP
        values as a function of shadow feature values (via spline fitting). Mismatched shadow
        feature values attenuate any residual chance relationship between SHAP and feature values,
        making the fitted spline flatter and shadow V closer to zero.
      </literature>
      <impact>
        The mismatch deflates shadow V estimates, which lowers the max-shadow noise threshold for
        the V exceedance test. This biases the test in the anti-conservative direction (makes it
        slightly easier for real effects to achieve significance on the V component). The practical
        magnitude is very small: shadow features are uninformative by construction, so shadow V is
        near zero regardless of whether the x-axis pairing is correct. The deflation moves shadow V
        from "near zero" to "slightly nearer zero." The M and GII components are not affected
        (M uses only SHAP magnitudes, not feature values; GII is a composite of M and V).
      </impact>
      <recommendation>
        Replace the fold-0 tiling with a concatenation that preserves each fold's shadow features:
        construct X_stacked by concatenating all chunks_X with proper index alignment, analogous
        to the OOF-mode path at line 1418. Specifically: X_stacked = pd.concat(chunks_X,
        ignore_index=True). This preserves each fold's shadow feature values while maintaining
        the K*N row count. The real feature columns are identical across folds, so the change
        affects only shadow columns. This eliminates the anti-conservative bias at negligible
        implementation cost.
      </recommendation>
